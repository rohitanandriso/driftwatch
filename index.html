The problem

Attacks can be safe one message at a time — and dangerous as a session.

Per-message controls are strong at obvious single-turn attacks. But gradual jailbreaks, incremental data leakage, repeated secret probing, and risky tool sequences can emerge only when the full session is considered.

Driftwatch changes the unit of analysis from the message to the session and continuously re-evaluates the accumulated state.

Architecture

One stateful control plane across prompts, responses, and tools.

Session-level detectors

Signals that only become visible when the firewall remembers.

↝

Intent Drift

Tracks the conversation trajectory across turns to surface gradual escalation patterns.

⌕

Secret Probing

Accumulates repeated attempts to obtain credentials, keys, passwords, and sensitive secrets.

∑

Exfiltration Budget

Counts cumulative sensitive-record release across the session instead of per response.

⛓

Tool Chain

Correlates individually authorized calls into risky sequences such as sensitive read → external sink.

↻

Refusal Probing

Detects persistent refuse → rephrase → retry loops commonly seen in automated multi-turn attacks.
