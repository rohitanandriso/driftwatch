The problem

Some attacks only exist across the session.

A strong per-message control can catch obvious single-turn attacks. But gradual jailbreaks, incremental data leakage, repeated secret probing, and risky tool sequences can remain individually acceptable while becoming dangerous in aggregate.

Driftwatch changes the unit of analysis from message to session. It retains state, re-evaluates it on every event, and can contain the agent when correlated evidence crosses policy thresholds.

Architecture

A stateful control plane at the AI trust boundary.

The same inspection engine can sit in front of model traffic or at the MCP tool boundary. Every event updates session state; detectors re-evaluate; the highest correlated verdict is enforced.

Session-level detectors

Signals that become visible when the firewall remembers.

↝

Intent Drift

Tracks conversation trajectory to surface gradual escalation patterns such as multi-turn jailbreak progression.

⌕

Secret Probing

Accumulates repeated requests for credentials, keys, passwords, and sensitive secrets across turns.

∑

Exfiltration Budget

Counts cumulative distinct sensitive records released across the session rather than per response.

⛓

Tool Chain

Correlates sensitive reads, untrusted content, and external sinks into higher-risk action sequences.

↻

Refusal Probing

Detects persistent refuse → rephrase → retry loops associated with automated multi-turn attacks.

Compromised MCP scenario

The tool server can be compromised. The boundary still has a vote.

Driftwatch can tag poisoned tool output as untrusted, detect a risky path toward an external sink, block the action, and quarantine the agent.
