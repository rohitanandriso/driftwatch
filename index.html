The problem

Some attacks only exist across the session.

A strong per-message control can catch obvious single-turn attacks. But gradual jailbreaks, incremental data leakage, repeated secret probing, risky tool sequences, and insider-risk data egress to public AI can remain individually acceptable while becoming dangerous in aggregate.

Driftwatch changes the unit of analysis from message to session. It retains state, re-evaluates it on every event, and can contain the agent when correlated evidence crosses policy thresholds.

Architecture

One stateful control plane. Three enforcement points.

Driftwatch follows the trust boundary rather than a single product surface. The same session-aware detection and policy model can protect conversational traffic, agent tool activity, and sensitive data leaving a managed browser for public AI services.

Browser Guard · Working prototype

Reduce insider risk before enterprise data reaches public AI.

Insider risk and inadvertent data exposure can bypass enterprise identity controls when sensitive information is sent to public AI destinations outside approved enterprise channels. Driftwatch Browser Guard moves enforcement to the managed-browser boundary: it inspects content before submission, correlates it with session context, and can warn or block when protected enterprise data is about to leave.
